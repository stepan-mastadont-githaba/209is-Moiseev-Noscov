git init -- инициирует новый репозиторий
git clone <url> -- клонирует удаленный репозиторий по url
git add <file> -- добавляет файл для последующего коммита. git add . для всех изменений
git commit -m "*сообщение*" -- коммитит указанные изменения
git status -- текущее состояние рабочей директории
git log -- выводит историю коммитов текущей ветки
git diff -- показывает изменения в файлах, которые еще не добавлены
git branch -- список локальных веток, git branch <имя> чтобы создать новую
git checkout <ветка> -- переключает на указанную ветку
git merge <ветка> -- сливает указанную ветку с текущей веткой
git pull <remote> <branch> -- отправляет на удаленный репозиторий
git remote -v -- показывает список репозиториев
git reset <commit> -- возвращает коммит к исходному состоянию
git revert <commit> -- создает новый коммит, который отменяет изменения
git stash -- сохраняет изменения во временное хранилище
git stash pop -- возвращает изменения из хранилища
git tag <имя> -- создает тег для коммита
git rebase <ветка> применяет коммит для другой ветки

# Виды цели и уровни интеграции программных уровней
Интеграция програмных модулей - это процесс объединения отдельных компонентов ПО в единую систему
цель интеграции:
    1. обеспечение взаимодействия модулей
    2. повышение надежности и производительности системы
    3. упрощение разработки и сопровождения ПО
    4. минимизация дублирования функционала

# виды интеграции программных модулей:
    1. по способу взаимодействия:
    горизонатльная интеграция:
        -объеденение модулей одного уровня
    вертикальная интеграция:
        -объеденение модулей разных уровней
    2. по степени связанности
        упрощает замену компонентов
        REST API и микросервисы
    -сильная связанность:
        изменение одного требуе модификации других
        пример: монолитная архитектура
    3. по времени выполнения:
    -статическая интеграция:
        компоненты связываются на этапе компиляции
    -динамическая интеграция:
        компоненты связываются во время выполнения
    
# Уровни интеграции ПО:
    0. уровень данных (БД)
    1. сервисный уровень (API)
    2. уровень пользовательского интерфейса (UI)
    3. Уровень бизнес-логики

### Источники и приемники данных

источник данных - это объект, который передает данные
приемник данных - это объект, который принимает данные

# источники данных:
    1. БД
    2. файлы
    3. api
    4. потоки данных

# приемики данных:
    1. БД
    2. отчеты и визуализации
    3. внешние системы
    4. облачные хранилища

критерии выбора источников и приемников
при выборе учитывают:
    1. формат данных (структурированный, полуструктурированный и неструктурированный)
    2. объем данных (большие объемы данных требуют структурированных систем)
    3. частоту обновления (realtime и пакетная обработка)
    4. надежность и доступность
    5. безопасность
    6. стоимость

сопоставление объектов данных - это процесс преобразования данных между источником и приемником
этапы сопоставления:
    1. анализ структуры данных (сравнение полей в источнике и приемнике)
    2. преобразование типов
    3. маппинг полей
    4. обработка отсутствующих данных
    5. валидация

проблемы и решения:
    1. несовпадение форматов - использовать унифицированные форматы
    2. потеря данных - логирование и мониторинг
    3. если проблема с производительностью - оптимизировать запросы и реализовать кеширование

# транспортные протоколы

основные трнаспортные протоколы:

    5. AMQP

Ручное и автоматизированное тестирование

Ручное тестирование - это процесс выполнения тест-кейсов без использования автоматизированных инструментов
Особенности: тестироващик запускает программу, вводит данные и наблюдает поведение

Преимущества и недостатки ручного тестирования:
    + Гибкость и адаптированность к неожиданныи ситуациям
    + Больше подходит для ui uix и сложных взаимодействий
    + Применяется на начальных этапах проекта
    - Время и ресурсозатратно
    - Возможны человеческие ошибки
    - Плохо масштабируется

Автоматизированное тестирование - использование специализированных скриптов или программ для тестирования

Инструменты:
    Selenium
    G-unit и PyTest
    Typress
    Appium
